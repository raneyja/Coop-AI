## Shared policy follow-up

Jon's active scope is scalable policy and enforcement, rather than replaying named repositories until their example answers pass. The current candidate implements rules that depend on the evidence and turn, with no repository or question exceptions:

- **Evidence boundaries:** the client owns the source-coverage sentence. Model-generated opening claims cannot expand it. The client prompt now describes complete conditions, exact implementation bindings, call boundaries, and prospective questions without prescribing serializer, transition, manager, or hunt-specific answers. Partial evidence and search misses do not establish absence or exhaustive coverage.
- **Discovery without fabricated facts:** topic words no longer acquire hand-written filename aliases or tool/class synonyms. Path relevance uses the user's terms without preferring serializers, server folders, mutator names, or penalizing type declarations. Question text cannot manufacture risk/absence flags. Only actual empty retrieval produces a coverage miss. Source windows are exact excerpts, without inferred class or writer identity or extra language-specific answer recipes. Literal relative import leads are followed only when the remote inventory supplies a unique exact path; aliases and ambiguous paths remain unknown.
