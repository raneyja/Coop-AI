# Repeatable integration publication regression

Required: a supported Node 22 runtime (22.23.3 or later within Node22), installed pinned repository dependencies, a local Docker Unix-socket context, and the already cached immutable image `pgvector/pgvector@sha256:00ba258a66dac104fd5171074a0084462a64a1369d8513f3d0a634e2f24d15bc`. The runner never pulls an image. Use a clean test environment without `DATABASE_URL`, PG target/session overrides or Docker target/config overrides; it refuses them before inspection or clients. Do not configure real model, vendor, account or mail credentials for this suite.

From the repository terminal:

```sh
npm run test:publication-regression
```

No manually assigned port, container ID, database URL, evidence JSON or test-source edit is needed. The runner creates a new random UUID name and run label, publishes PostgreSQL only to `127.0.0.1` on a Docker-assigned port, and uses tmpfs with no mounted/persistent volumes. Database/user/password are fixed synthetic fixture values. It verifies the actual Docker ID, name, image, creation time, labels, running state, commands, environment, port binding and tmpfs/no mounts before clients. Each suite independently re-inspects Docker; a recorded JSON file alone is not authority. The existing pure database-target owner admits the constructed loopback URL. It accepts no caller-supplied URL or query/session overrides.

The maintained `integrationApi.publication.fixture.ts` entry builds reproducibly to `dist/tests/publication-main.cjs` with the backend bundle settings, never into product entrypoints. The actual main factory/auth/session/policy/encrypted-store owners execute against fresh PostgreSQL. An existing schema/ledger refuses the initial run: no DROP, TRUNCATE, adoption, quarantine clearing or replacement of another service is allowed. Immutable migrations 001–036 are the same product prerequisites.

The original36 main/PG groups are retained, including the actual late-revocation window, mutation ordering, expiry, SAML/key/role/plan/source admission, disconnect, deadlock, lock timeout, checkout exhaustion and private serialization refusal. Three additional maintained controls preserve API-key revocation order, acknowledged password-policy refusal and same-metadata credential-generation rotation refusal after retrieval. Vendor fetches are intercepted with synthetic replies, not live account qualification. Pure metadata policy tests do not certify a real Docker fixture; the full suites provide that layer.

Test files execute directly through Node's `node:test` registration on the owned child process. This avoids an extra test-worker process surviving cancellation. Each required child has a120second monotonic bound. Expiry/cancellation is recorded before SIGTERM, with SIGKILL escalation if needed; a child that catches SIGTERM and exits zero still fails. Required completion waits for physical close and drained logs, preserving actual exit/signal/deadline metadata. Seven real child-process controls run before fixture creation. Runner SIGINT/SIGTERM cancels its own child and returns nonzero. Finally, it re-verifies immutable ID/name/run label/image/creation/commands/environment/loopback configuration/tmpfs/no mounts before removing only its exact container and confirms that ID is absent. Cleanup grants no database access and can remove an exactly owned stopped service even though its live ports disappeared; database admission continues to reject that service. Required test failure, cancellation, unsafe target, missing image, identity mismatch or unconfirmed cleanup cannot yield a success result. Incomplete fault runs never report39 controls passed.

The printed private temporary artifact directory retains image/fixture/process identities, TAP/build logs, final result and cleanup metadata. It contains only synthetic fixture information. Preserve these identities when investigating a failure. A hard kill of the runner, machine/daemon loss, malformed or unknown fixture can require separately authorized cleanup; this is not a crash-safe janitor or permission to delete containers by a broad prefix. No success is claimed when cleanup cannot be confirmed.

The immutable cached image's locally inspected provenance is PostgreSQL16.14 on Linux/arm64 under Docker Desktop. Its local digest is recorded; current Linux/amd64 CI image availability/provenance and full workflow execution remain unqualified until that exact platform/runtime is independently tested. The new npm command is a required scoped regression invocation, not a claim that the existing broad `test:ci` workflow already provisions Docker or runs it. CI ownership must provision the reviewed cached image and wire this invocation as an actual required job after independent acceptance. No test skip/fallback without Docker or a database is provided.
