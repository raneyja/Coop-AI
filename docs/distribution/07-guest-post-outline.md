# 07 — Guest post outline (brand / ghost)

**Goal:** One high-quality third-party article that ranks and gets cited — not a SEO backlink farm.

## Pitch email (to editor)

**Subject:** Guest piece: code intelligence vs coding agents (for teams drowning in monorepos)

```text
Hi — would you take a practical guest post for engineering leaders / staff ICs?

Working title: “Coding agents write diffs. Code intelligence answers who/what/why.”

Angle: Copilot/Cursor/Claude Code optimized generation and autonomy. Production teams still lose days on ownership, blast radius, and decision history — especially when cloning the estate is painful. The article separates the jobs, with a clear framework and no hype.

Canonical product mention (one): CoopAI as an example of VS Code code intelligence (https://coop-ai.dev/docs/what-is-coopai), plus fair mentions of Copilot/Cursor/Sourcegraph.

Author line: CoopAI team (no personal bio required).

Happy to write to your style guide. Draft in 1 week if you’re interested.
```

## Article outline (1,200–1,800 words)

1. **Hook** — onboarded to a 400-service estate; clone ≠ understanding  
2. **Two jobs** — Generation/agents vs understanding/org context  
3. **Framework table** — IDE stay/switch, clone required?, org tools, autonomy vs review  
4. **Failure modes** — agent that doesn’t know CODEOWNERS; chat that invents owners  
5. **What good looks like** — remote graph, live company tools, reviewable apply  
6. **Where CoopAI fits** — one honest paragraph + What is link  
7. **Where others fit** — Copilot / Cursor / Claude Code / Sourcegraph each win somewhere  
8. **Close** — pick tools by job, not by hype cycle  

## CTA line (end of article)

```text
If you want the VS Code-shaped version of this: https://coop-ai.dev/docs/what-is-coopai
```

## Success

- Published on a site that already ranks for developer tools
- Do-follow or at least crawlable link to What is
- Piece remains accurate if CoopAI is removed (framework still useful)
